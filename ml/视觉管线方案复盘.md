## 0. 一句话定位

这套是**「frozen CLIP backbone + 线性探针 + 主动学习闭环」的单图个性化审美分类器**。
经过四版迭代与一轮严谨消融，已确认：**模型侧（backbone / 特征 / 范式）基本探到头，
当前与未来的瓶颈都在「标注信号质量」和「任务定义」侧。**

---

## 1. 方案全貌（现状快照）

- **技术栈**：open_clip `ViT-B-32`（laion2b，512 维，冻结）→ 抽图像 embedding →
  `StandardScaler + LogisticRegression`(class_weight=balanced) → joblib 落地。
- **判断单位**：单张图（对齐"一张张挑图"的真实逻辑，一条笔记有 2-3 张合格图就保留）。
- **闭环**：`predict` 识图分拣 → 人工纠错 → `merge` 合并 → `train` 重训 → 越用越准。
- **评估**：StratifiedGroupKFold（按笔记/来源分组，防同笔记相似图泄漏）。

|---|---|---|---|---|---|---|

## 2. 技术判断：这套"老旧"吗？

**结论：范式不老，组件偏老——但实测表明换组件在本数据上没用（见第 4 节）。**

- **范式不老**：在 2026 年，「冻结强 backbone + linear probe + 主动学习」依然是
  **千级样本、纯个人偏好任务的标准强 baseline**。样本少、口味个人化、要本地快速迭代闭环，
  这正是它最擅长的场景。重训大模型在这个数据量下只会过拟合。
- **偏老的组件**：ViT-B-32 是 CLIP 系列里较弱的（2021，512 维）；特征单一（只有一个全局语义向量，
  无美学专用 / 构图 / 人脸等结构信号）。
- **但是**——第 4 节的实测把"换组件能涨分"的假设证伪了。**别把"看起来老"等同于"该换"。**

## 3. 业界对标（2024–2026，针对"个性化视觉偏好"）

| 档位 | 方案 | 代表 | 适合谁 |
|---|---|---|---|
| **A. 轻量个性化** | frozen 强 backbone + linear probe / 小 MLP | SigLIP2 / DINOv2 / EVA-CLIP | **就是本项目**，小样本个人偏好的主流且正确选择 |
| **B. 偏好打分器(reward model)** | 在 CLIP/BLIP 上用**人类 pairwise 偏好**微调出标量分 | PickScore、ImageReward、HPSv2、MPS | 想要稳定"喜好分"、做排序 / 挑 top-K |
| **C. MLLM 当裁判(最前沿/最贵)** | 多模态大模型直接打分或排序 | Q-Align、Qwen2.5-VL、InternVL2.5、Claude/GPT-4o as judge | TS 端 DashScope `visualFilter` 已是此思路 |

**真正的趋势是 B/C 与 A 融合**：用 MLLM 的强理解力**离线产出软标签 / 中间特征**，
再用轻量个性化头学"懂你"的部分——既懂图又懂你，且 MLLM 不必每张实时调（省钱）。
这是"顶尖但务实"的路线，**不是把大模型整个微调一遍**。

## 4. 被实测证伪的方向（最重要的一节）

Mac 侧早期给过几条"进阶建议"，Windows 侧用同口径消融逐一验证，结果如下：

| 早期建议 | 实测结论 | 判定 |
|---|---|---|
| 换 backbone（SigLIP2-L / DINOv2-L）是单点最大收益 | SigLIP2-L vs ViT-B-32 **打平**（0.836 vs 0.831，噪声内） | ❌ 本数据上不成立 |
| 加 LAION 美学分当额外特征 | 单独 0.690 有信号，但拼进去仅 **+0.003、FP 没降** | ❌ 被 CLIP 特征冗余覆盖 |
| 先修 GroupKFold 防数据泄漏 | 已修，随机CV≈分组CV，**确认无泄漏** | ✅ 核心隐患解决 |
| 转 pairwise 排序范式 | `train_pairwise.py` 试水仅 **+0.005** | ❌ 暂不切换（原因见第 7 节） |

**结论：模型侧三条路（backbone / 特征 / 范式）都被堵死。**
这反而印证了核心原则——**"别先换栈，先归因；模型是地板，标注和任务定义才是天花板。"**
瓶颈完全在数据侧和任务定义侧。

## 5. 当前真问题：FP 偏高 / 精确率 0.736

第四版混淆矩阵：TP=630 TN=1668 **FP=226** FN=179。

- **含义**：模型说 good 的图里，**约 1/4 实际是 bad**（精确率 0.736）。这是当前最大痛点。
- **现行策略**：持续补"看着像 good 但其实 bad"的难负样本，靠闭环纠错收紧边界。方向对。
- **两个要警惕的隐患**：
  1. **可能在撞自我一致性天花板**，而非数据不够。精确率卡在 0.73，很可能是审美边界本身的
     标注一致性就这么高，补再多数据也突破不了（验证方法见第 6、7 节）。
  2. **不平衡被推得更歪**。good:bad 已 1:2.3，无脑补负样本会让比例更偏，
     压 FP 的同时迟早伤召回（目前召回还在升是因为补的量大，边际会递减）。

## 6. 归因诊断框架（效果不佳时，先做这个，别先换栈）

"效果不佳"有四种本质不同的病因，解法相反。先花半天分清楚：

| 病因 | 怎么诊断 | 典型信号 | 对应解法 |
|---|---|---|---|
| **① 特征瓶颈** | 把判错对在特征空间可视化(UMAP) | 你一眼能分对，但两图特征挨得极近 | 换/拼 backbone、加局部特征（**本项目已排除**） |
| **② 标注信号瓶颈**（最常见） | 同批边界图隔几天**自己重标**，算自我一致性 | 自己跟自己只有 ~78% 一致 → 天花板就在这 | 清洗矛盾标注、升级标注协议、正规化主动学习 |
| **③ 任务定义瓶颈** | 看错例是不是"脱离上下文没法判" | 单图看不出好坏，要靠同组对比/配文 | 转条件偏好（笔记内排序）、多原型个性化 |
| **④ 模型容量瓶颈**（最少见） | 训练集本身都拟合不好 | train acc 也低 | 才轮到微调（linear probe 几乎不会到这） |

**关键**：②的天花板 = 你自我一致性的上限。若自我重标只有 0.78，模型做到 0.74 就快触顶，
此时换 DINOv3、上 MLLM 全是浪费。**先测自我一致性，再决定投哪。**

---

## 7. 下一步路线（按 ROI 从高到低）

### 7.1 先测自我一致性（0 成本，最高优先）
把 200 张边界图（P=0.4~0.6）隔几天自己重标一遍，算两次标注的一致率。
- 若一致率明显高于 0.736（比如 0.88）→ 还有空间，继续优化；
- 若一致率也就 0.78 → **0.736 已逼近极限**，继续补数据低 ROI，该换打法（见 7.4 / 7.5）。

### 7.2 FP 错例聚类（最高 ROI 的 data-centric 打法）
把 226 个 FP 的 CLIP 向量聚类，看是不是扎堆在某几类（如"精致商品摆拍""儿童戴帽""货架但构图好"）。
**若 FP 聚成 3~4 簇，针对那几簇定向补样，比泛泛补难负样本高效一个量级。**
脚本见[附录 A](#附录-afp-错例聚类脚本)。

### 7.3 看 precision@K + 拒答带（改善体验，不堆数据）
实际用途是"挑出最好的图"，真正该看的是**高置信段精确率**，而非 0.5 阈值的全局 0.736。
- 看 **precision@K / PR 曲线**：P(good)>0.85 那段精确率大概率 0.9+；
- 上**拒答带**：让 0.45~0.65 的边界图直接交人工，模型只对高置信区负责。
  把"准确率问题"转成"省人力问题"，体验立刻变好。

### 7.4 任务定义条件化（大改，看 7.1 的天花板再定）
若自我一致性证明单图绝对判断已到顶，根因可能是"单图脱离上下文判不准"
（同一张图在"高级穿搭"语境是 good、在"杂乱商品流"是 bad）。
→ 从"单图二分类"转"**笔记内 / 场景内排序**"，或用聚类发现 2~4 个口味原型做**多原型个性化**
（承认一个人审美内部本就有多种 mood，别硬塞进一个分类边界）。

### 7.5 pairwise 真正该上场的时机
pairwise 只 +0.005 **不代表它没用**，而是"在现有 good/bad 标签上转范式"——标签信息量没变，
换 loss 当然边际。它的价值在于**用 A-vs-B 协议重新采集标注**（相对判断噪声远低于绝对二分类）。
→ 若精确率确实卡死在自我一致性天花板，**重新用成对协议标注**才是它该登场的时候。

### 7.6 顶尖技术栈：何时才值得，以及代价
仅当 ①③ 做完、② 天花板足够高、数据量也上来了，才考虑。按门槛从低到高：

| 技术栈 | 解决什么 | 数据/成本门槛 | 风险 |
|---|---|---|---|
| 训练专属 reward model（CLIP/BLIP 上微调 pairwise） | 比 linear probe 更贴合偏好流形 | 几千–上万对，单 GPU | 中，需严格 GroupKFold |
| backbone 端到端微调（LoRA / 部分解冻） | 让特征本身向你的审美偏移 | **万级以上**才划算 | 高，小数据必崩 |
| MLLM 个性化（Qwen2.5-VL/InternVL + LoRA 当裁判） | 既懂图又能语言解释 | 贵，需指令数据 + GPU | 高成本，推理慢 |
| **VLM 软标签 + 轻量个性化头（混合架构）** | MLLM 理解力 + 小头学个性化 | 中，MLLM 离线跑一次 | **推荐的"顶尖但务实"路线** |

> 诚实结论：个人审美任务在万级样本以下，**端到端微调大 backbone 几乎总是亏的**
> （过拟合 + 灾难性遗忘）。真要上顶尖，选**混合架构**，不是微调整个大模型。

---

## 8. 关键原则备忘（一页纸版）

1. **别先换栈，先归因**——模型是地板，标注信号和任务定义才是天花板。
2. **data-centric > model-centric**——这个规模下，清洗 200 个矛盾标注 > 把模型换大一档。
3. **评估指标要对**——"挑图"看 **precision@K / NDCG**，不是分类准确率。
4. **拒答比硬判实用**——低置信交人工，比逼模型在边界硬判更省力、体验更好。
5. **打平时选简单的**——backbone 打平就选快的、维度小的、历史可比的（已落实为 clip-b32）。
6. **承认审美会漂移**——先量自我一致性，知道天花板在哪，再决定值不值得继续投。

## 附录 A：FP 错例聚类脚本

> 用途：读训练报告里的误判清单，挑出 FP（真值 bad、却被判 good），抽 CLIP 特征做 KMeans 聚类，
> 看模型在哪几类图上栽得最多，从而**定向补难负样本**而非泛泛补量。
>
> 运行（Windows，复用 run.ps1 的 Python 环境）：
> ```powershell
> .\ml\run.ps1 ；# 确认环境后，直接用其定位到的 python 跑：
> <accio-python> ml\analyze_fp.py --top-k 4 --out ml\data\fp_clusters
> ```
> 依赖与 `clip_utils.py` 一致（open_clip + torch + sklearn）。脚本会把每簇的代表图复制到
> `fp_clusters/cluster_<i>/`，方便你一眼看出"模型把哪类 bad 误当 good"。

```python
# ml/analyze_fp.py
"""FP 错例聚类：找出模型最常把哪几类 bad 误判成 good。

读 ml/model/train_report.json 的 errors（true=bad & pred=good 即 FP），
抽 CLIP 特征 -> KMeans 聚类 -> 每簇复制代表图到输出目录，并打印簇规模。
"""
import argparse, json, shutil, sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parent))
import numpy as np
from sklearn.cluster import KMeans
from clip_utils import embed_image

ROOT = Path(__file__).resolve().parent.parent
REPORT = ROOT / "ml" / "model" / "train_report.json"


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--top-k", type=int, default=4, help="聚成几簇")
    ap.add_argument("--out", default="ml/data/fp_clusters", help="代表图输出目录")
    ap.add_argument("--per-cluster", type=int, default=12, help="每簇复制几张代表图")
    args = ap.parse_args()

    if not REPORT.exists():
        print(f"[err] 找不到 {REPORT}，请先训练生成 train_report.json")
        sys.exit(1)

    report = json.loads(REPORT.read_text(encoding="utf-8"))
    fps = [e for e in report.get("errors", []) if e["true"] == "bad" and e["pred"] == "good"]
    print(f"[info] FP（bad 被判 good）共 {len(fps)} 张")
    if len(fps) < args.top_k:
        print("[err] FP 太少，无需聚类")
        return

    paths, vecs = [], []
    for i, e in enumerate(fps, 1):
        p = ROOT / e["path"]
        if not p.exists():
            print(f"[warn] 跳过缺失文件: {e['path']}")
            continue
        paths.append((p, float(e.get("prob_good", 0))))
        vecs.append(embed_image(p))
        if i % 25 == 0 or i == len(fps):
            print(f"  [embed] {i}/{len(fps)}")

    X = np.stack(vecs)
    km = KMeans(n_clusters=args.top_k, n_init=10, random_state=42).fit(X)
    labels = km.labels_

    out = ROOT / args.out
    print(f"\n=== FP 聚类结果（k={args.top_k}）===")
    for c in range(args.top_k):
        idx = np.where(labels == c)[0]
        # 离簇心最近的当代表
        center = km.cluster_centers_[c]
        order = sorted(idx, key=lambda j: np.linalg.norm(X[j] - center))
        print(f"簇 {c}: {len(idx)} 张  (占 FP 的 {len(idx)/len(labels)*100:.0f}%)")
        cdir = out / f"cluster_{c}"
        cdir.mkdir(parents=True, exist_ok=True)
        for rank, j in enumerate(order[: args.per_cluster]):
            p, prob = paths[j]
            pct = int(round(prob * 100))
            shutil.copy2(p, cdir / f"{pct:03d}_{rank:02d}_{p.name}")
    print(f"\n[done] 代表图已复制 -> {out}")
    print("       逐簇打开看：模型把『哪一类 bad』最常误当 good，就定向补那一类难负样本。")


if __name__ == "__main__":
    main()
```

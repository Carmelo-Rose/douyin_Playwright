# Social Monitor

独立的社媒观察脚本目录，不接入原来的 `npm run capture` 主流程。第一版先做微博关键词搜索样本抓取，后续再基于导出的图片链接加看图判断。

## 当前能力

- 平台：微博搜索
- 运行方式：手动运行，不做定时任务
- 默认目标：观察「明星 / 帽子 / 戴帽子 / 机场 / 同款」相关内容
- 输出：Excel，写入根目录 `output/`
- 登录态：单独使用 `.user-data/weibo-monitor`

## 配置

配置文件：

```text
social-monitor/config.weibo.json
```

默认搜索词：

```json
[
  "明星 帽子",
  "明星 戴帽子",
  "明星 机场 帽子",
  "明星 同款 帽子"
]
```

常改字段：

- `searchQueries`：微博实际搜索词，第一版主要改这里观察效果
- `relevanceKeywords`：导出时记录命中的关键词，方便后续筛样本
- `excludeKeywords`：负向过滤，正文命中其中任意词就直接丢弃。用来排除「帽子」的非实物含义和黑话，如 `扣帽子`（甩锅）、`帽子叔叔`（警察黑话）、`学士帽`、`巫婆帽`、`绿帽子`、`安全帽` 等，可按观察到的噪音继续补充
- `maxScrolls`：每个搜索词滚动次数
- `captureTimeoutMs`：等待页面结果的时间
- `headless`：默认 `false`，方便登录和观察页面
- `userDataDir`：微博登录态目录
- `outputDir`：Excel 输出目录
- `realtime`：默认 `false`，用微博**综合/热度排序**（信号更好，相关帖一般有图）；设为 `true` 走「实时」标签按时间倒序抓最新，但噪音明显更多（广告号、把「帽子」当比喻的吐槽帖等）
- `recentDays`：默认 `7`，只抓最近 N 天的微博（用微博高级搜索的时间范围，跟排序方式独立，可与综合排序同时生效）；设为 `0` 表示不限制时间
- `requireImage`：默认 `true`，丢掉没有正文配图的帖子。因为最终目标是「看图判断有没有帽子」，纯文本帖（小说、广告文案、「扣帽子」吐槽）用不上
- `requireKeywordMatch`：默认 `false` 全量导出；设为 `true` 时只保留正文命中 `relevanceKeywords` 的微博，减少噪音
- `queryDelayMs`：多个搜索词之间的基础间隔（毫秒），实际等待为 1~2 倍随机值，降低被风控概率

## 运行

```powershell
npx tsx social-monitor/weibo-demo.ts
```

指定配置：

```powershell
npx tsx social-monitor/weibo-demo.ts --config social-monitor/config.weibo.json
```

临时覆盖搜索词：

```powershell
npx tsx social-monitor/weibo-demo.ts --query "明星 帽子"
```

可以传多个 `--query`：

```powershell
npx tsx social-monitor/weibo-demo.ts --query "明星 帽子" --query "明星 机场 帽子"
```

## 输出

结果会写到 `output/weibo-posts-<关键词>-<时间>.xlsx`。

字段包括：

- 搜索词
- 匹配关键词
- 微博ID
- 正文
- 作者
- 发布时间
- 来源
- 互动信息
- 微博链接
- 作者链接
- 图片链接
- 抓取时间

图片链接会尽量只保留微博正文配图，避免头像、会员图标等小图标干扰后续看图判断。

> 说明：
> - 长微博的「展开全文」正文会被完整抓取（读取隐藏的完整节点，无需点击展开）。
> - 每抓完一个搜索词就会增量写一次 Excel，中途被风控或中断也不会丢失已抓到的结果。
> - 单个搜索词出错只会跳过该词并继续，不会让整轮失败。

## 登录态

脚本使用 `.user-data/weibo-monitor` 保存微博登录态。首次运行如果微博要求登录，在打开的浏览器里手动登录即可，脚本会等待搜索结果出现后继续。

## 第二段：视觉打分（score-images.ts）

抓取（第一段）只看文字，分不清「明星戴帽出街」和「保健品广告」。第二段把每条微博的图片发给视觉模型（小米 MiMo，Anthropic 兼容接口）判断，回写打分列。两段解耦，互不影响。

判定目标：**明星本人戴着帽子出街 / 机场 / 街拍的真实照片**。

### 配置（.env，不进 git）

```text
MIMO_API_KEY=你的key
MIMO_BASE_URL=https://token-plan-cn.xiaomimimo.com/anthropic
MIMO_MODEL=mimo-v2.5
```

### 运行

```powershell
# 默认对 output/ 里最新的 weibo-posts-*.xlsx 打分
npx tsx social-monitor/score-images.ts

# 先小批量试跑（省钱），只分析前 5 条
npx tsx social-monitor/score-images.ts --limit 5

# 指定输入文件
npx tsx social-monitor/score-images.ts --input "output/weibo-posts-xxx.xlsx"
```

可选参数：
- `--only-good`：**只导出合格（绿/黄）的行，红的（没帽子或没明星，如盒马烧烤广告）直接剔除**。这是日常出成品用的开关——打开后表里全是「帽子+明星」对的。
- `--push`：把**新增**的合格内容推送到企业微信群（webhook 配在 `.env` 的 `WECOM_WEBHOOKS`，多个用逗号分隔，会同时发到所有群）。
- `--rescore`：忽略缓存，强制重新打分（改了打分逻辑后用）。

### 跨天去重（自动）

状态文件 `social-monitor/.state/weibo-seen.json` 按微博 ID 记录每条的打分结果和是否已推送：
- **已打过分的** → 直接用缓存，不重复调模型（省 token）。
- **已推送过的** → 不再推送，`--push` 只发**从没推过的新增合格内容**。

所以「今天抓了明天再抓」即使数据重复，也不会重复打分、不会重复推送。要完全重置：删掉这个状态文件即可。
- `--limit N`：只分析前 N 条（省钱试跑）。
- `--max-images N`：每条取前 N 张图，默认 1，越多越准也越贵。
- `--concurrency N`：并发，默认 3。

> 为什么需要这一步：微博搜索对稀疏的话题会掺「你可能感兴趣」的当红热帖（如盒马烧烤季），靠换搜索词治不了。所以原始抓取表（`weibo-posts-*`）一定带杂，**用本步按「帽子+明星」过滤后**（`weibo-scored-*`，配 `--only-good`）才是干净成品。

### 输出

生成 `output/weibo-scored-<原名>.xlsx`，在原有列后追加：

判定只看两个条件：**①画面里帽子清晰可见（核心产品，第一位）②是明星（必要）。** 场景（街拍 / 机场 / 综艺 / 品牌同款图）一律不影响判定。

| 列 | 含义 |
|---|---|
| 明星候选 | 从超话 / @提及 提取的明星名（文字层，较可靠） |
| 综合判断 | 绿（能用）/ 黄（凑活）/ 红（没用），带单元格底色 |
| 视觉相关度 | 0–100 分，以「帽子是否清晰」为主 |
| 帽子清晰 / 有人戴帽 / 像明星 / 帽子类型 | 视觉模型的判断 |
| 判断理由 | 一句话，方便人工复核 |
| 已分析图 | 实际送去识别的那张图链接 |

结果按 绿→黄→红、再按分数排序，好的自动浮到最上面。

打分逻辑（帽子优先、明星必要、场景不限）：
- **帽子不清晰 → 红**（产品是核心，没帽子直接淘汰，哪怕有明星）
- **没有明星线索（超话/@ 都没有，且看着不像艺人）→ 红**
- 帽子清晰 + 有明星 + 真人戴着 + 分数≥55 → **绿**
- 帽子清晰 + 有明星，但只是产品图没人戴 / 证据偏弱 → **黄**

明星线索分三层，优先级从高到低：
1. **带货名单核对**（最准）：正文/作者命中 `内娱艺人带货等级清单.xlsx` 里的名字 → 确认明星，并写出「带货等级」（S+/S/A+…），可据此优先追 S+ 的同款。
2. **超话 / @提及**：名单没有时，用微博自带的超话名、@提及兜底（如王赫野）。
3. **视觉**：以上都没有时，看图片像不像明星的专业拍摄（如王菲这种没超话的头条文章，也能捞回）。

名单文件默认读根目录 `内娱艺人带货等级清单.xlsx`，可用 `--celeb-list <路径>` 指定；找不到就跳过名单这层、仅用 2/3。输出新增「带货等级」列。

> 名单第二个 sheet「抖音头部达人种草表」是给以后接抖音用的，当前微博流程未使用。

> 说明：
> - 明星身份靠微博自带的「超话 / @提及」识别，不让视觉模型猜人脸（小众爱豆容易认错）。
> - 图片走「下载→base64」发送（带微博 Referer），比让模型直接抓 URL 稳。
> - 已能覆盖「画面里有帽子但正文没提」——因为这一段是真的在看图。
> - 每 5 条增量保存一次；单条识别失败标「错误」并跳过，不影响整体。

## 边界 / 后续

- 平台目前只有微博；抖音 / 小红书未接（建议下一步抽象统一的 Platform 接口再扩展）。
- 还没做自动定时；要定时需补「跨次运行按微博 ID 去重」，避免重复抓取和重复打分烧钱。
- 微博页面结构或风控策略变化时，可能需要调整选择器或登录态。
- 视觉判断准确率取决于模型；`mimo-v2.5` 实测对「广告图 / 商品图 / 无人戴帽」过滤效果不错，但仍建议人工扫一眼绿/黄两档。
